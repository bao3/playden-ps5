# Downloads proxy implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans (tasks are tightly coupled; do not split them across parallel implementers). Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Settings › Downloads proxy (Off/HTTP/SOCKS5, host, port, optional auth, Global checkbox default off) and ship a fork pre-release in the upstream zip layout.

**Architecture:** `NetworkProxy` is a process-wide snapshot. `HttpClient` and `WebSocketClient` bind it per transfer. Download callers set `HttpRequest::download_proxy`. Everyone else is proxied only when Global is set. Loopback is always direct. Changing the snapshot bumps a generation that drops the shared CM WebSocket.

**Tech Stack:** C++17, pinned libcurl 8.22, preferences.conf, ps5-homebrew-ui settings rows, GitHub Actions on bao3/playden-ps5.

## Global Constraints

- Fork only: https://github.com/bao3/playden-ps5. No upstream PR, no upstream release, no push to `main` without approval.
- Do not change `CMakeLists.txt` `VERSION`, `src/runtime/kit_trust.h`, or the kit entry in `dependencies.lock.json`.
- Prerelease identity is `beta.9001` (`0.11.0-beta.9001`), published as a pre-release, never latest.
- Reuse `playden-kit-0.20.zip` only after SHA-256 `959acf877a82b2711454fd62ba4a9a7c0476ee24627e92511283aeb54ace5a46`.
- TLS verification stays on. No direct fallback when a proxy is selected. No credentials in logs.
- Loopback (`127.0.0.0/8`, `localhost`) and ShadowMount stay direct.
- GPL-3.0-or-later SPDX on new product sources. Match surrounding style. No unrelated refactors.
- Do not install on a console.
